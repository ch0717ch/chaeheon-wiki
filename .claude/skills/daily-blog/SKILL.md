# 블로그 배치 루틴 (규칙 v2, 2026-11-13부터)

**규칙 원문은 `blog/strategy/rules-v2.md` — 먼저 끝까지 읽는다.** 이 문서는 실행 순서만 적는다.
사용자가 이 루틴을 부르면 **질문하지 말고 끝까지 진행**한다. 사용자에게 내용을 직접 붙여넣어 달라고 요청하는 것은 영구 금지.

| 블로그명 | 키 | 주제 | 카테고리(파일명) | 배치 크기 | 예약 시작 |
|---|---|---|---|---|---|
| 겜테크 | `tech` | 게임 + AI·기술(가전·기기) | 게임 / AI기술 | 10 | 07:00, 1시간 간격 |
| 대학생 | `campus` | 장학금·봉사·대외활동 | 장학금 / 봉사 / 대외활동 | 10 | 07:30, 1시간 간격 |
| 본진 | `biz` | 생활경제 문제해결형 (뉴스 해설 금지) | 비즈니스 / 경제 / 사회 | 5~7 | 08:00, 2시간 간격 |

설정은 `blog/blogs.json`(batchName, v2Categories, scheduleOffsetMin, scheduleIntervalMin).
블로그별 키워드 기준은 rules-v2.md 1번. 글쓰기 기본기는 `anthropic-skills:adsense-blog-writing` 스킬도 함께 적용.

## 입력 해석

- "오늘의 키워드" / "오늘의 키워드 N개" → 세 블로그 모두 배치 크기대로 (본진 5~7). 원글을 따로 안 받았으면
  겜테크·대학생은 지난 글(`blog/posts/<키>/*/*/meta.json`) 중 시즌성 있는 글을 원글로 골라 **시리즈 모드로 배치의 절반 이상**을 채운다.
- "블로그명 + 키워드 N개" → 일반 모드, 키워드 1개당 글 1개 (그 블로그만).
- "시리즈: [원글 제목/URL]" → 원글과 겹치지 않는 파생 글 3~5개. URL이면 도구로 직접 읽는다(Claude in Chrome 우선, 막히면 막힌 지점만 짧게 알리고 진행).

## 1단계 — 키워드 고르기 (WebSearch, mode=extended, 여러 개를 한 번에)

1. 지난 글 키워드를 블로그별로 먼저 확인해 중복을 피한다.
2. **검색 수요가 2일 이상 이어지는 키워드만.** 하루 반짝 당일 이슈 제외.
3. 겜테크: 구매 의도형(비교·추천·가성비) 반 + 문제해결형(설정·오류·사용법) 반. 게임은 일정 있는 키워드(출시·업데이트·쿠폰·사전예약), AI는 써먹는 법.
4. 대학생: 해마다 반복되는 시즌 키워드. 제목에 연도·차수. 초중고 학부모 대상 제외.
5. 본진: 내 돈·생활 문제해결형(지원금 신청, 세금·환급, 근로장려금, 청년 금융상품 비교, 4대보험, 월세·전세 지원, 카드·통장 비교). 시황·정책 해설·사건 정리 금지. 학생 신분 혜택은 대학생 블로그로.
6. 날짜·금액·조건은 공식 공고·기관 페이지로 확인할 수 있는 것만. 공식 URL 1~3개를 실제로 확보해 둔다(확인 못 한 URL은 쓰지 않는다).
7. 배치 전체의 도입·마무리 유형과 제목 어미를 **먼저 배정표로** 만든다 (rules-v2.md 4·5번: 연속 금지, 10개 기준 유형당 최대 3, "정리해봤어요" 2개 이하).

## 2단계 — 글 폴더 만들기

각 글: `blog/posts/<키>/<날짜>/<NN>-<짧은-한글-슬러그>/` 에 `source.md` + `meta.json` (thumb.json 은 더 이상 쓰지 않는다).

**source.md** (문법: `blog/tools/build-batch.mjs` 상단 주석)
- 첫 2~3문장에 검색 질문의 핵심 답. 도입은 배정된 유형대로.
- 소제목 `##` 은 검색할 법한 질문형을 섞는다. 숫자·조건·일정·비교는 **표**(표로 만들 수 있으면 반드시 표).
- 네이버 기능 활용: 표, `> 인용구`, `---` 구분선, `**굵게**`, `==형광펜==`, 번호 목록. 박스는 `:::box`.
- 공식 출처 링크 `[이름](https://...)` 1~3개를 본문 안에. 빈 링크·추측 URL 금지.
- 마무리는 배정된 유형대로(체크리스트 / 다음 행동 제안 / 주의사항 한 줄 / 질문 던지기 / 일정 리마인드 / 짧게 끝내기).
  `:::summary` 를 쓸 땐 제목에 "정리" 금지.
- 금지: "정리하면", "정리했습니다", "~알아보겠습니다", "결론적으로", "오늘은 ~에 대해", 사전식 정의 첫 문장, "함께 보면 좋은 글",
  같은 접속어(또한·그리고·따라서) 반복, 지어낸 경험·후기·통계, `[사진]`.
- **공백 포함 1,500자 이상** (채우기용 문장 금지). 본진은 계산 예시나 비교표 최소 1개.
- 마지막 줄 `※ <날짜> 기준 …`.

**meta.json**
```json
{
  "no": "01", "keyword": "국가장학금 1차 신청기간", "category": "장학금",
  "mode": "시리즈", "seriesOf": "원글 제목 (일반 모드면 생략)",
  "intro": "결론 먼저형", "outro": "짧게 끝내기",
  "titles": ["네이버용 제목 3개 — 길고 부드럽게 말 거는 톤, 어미 섞기"],
  "hashtags": ["# 없이 정확히 30개, 중복 없이"],
  "cover": { "title": "국가장학금 1차\n**신청기간** 확인", "subtitle": "2027년 1학기 · 재학생은 1차가 원칙", "badge": "2027 1학기" },
  "shoppingConnect": "겜테크 구매 의도 글만: '추천 모델 비교' 표 바로 아래",
  "sources": ["기관명 — https://..."]
}
```
- intro: 질문형 | 상황 묘사형 | 뉴스 맥락형 | 결론 먼저형 | 비교표 먼저형
- outro: 체크리스트 | 다음 행동 제안 | 주의사항 한 줄 | 질문 던지기 | 일정 리마인드 | 짧게 끝내기
- cover.title 은 최대 3줄, 한 줄 9자 안팎. `**강조**` 는 카테고리 색. 썸네일 문구는 본문에 있는 내용만.
- schedule 은 비워 두면 자동 배정 (특정 시각이 필요할 때만 "HH:MM").

## 3단계 — 빌드·검수·썸네일·압축 (블로그마다)

```bash
node blog/tools/build-batch.mjs blog/posts/<키>/<날짜>     # 배치 폴더에 NN_키워드(카테고리).html + 배치정보.md, 자동 검수
node blog/tools/render-cover.mjs blog/posts/<키>/<날짜>    # NN_키워드(카테고리)_썸네일.png
python3 blog/tools/pack-batch.py blog/posts/<키>/<날짜> --out <스크래치패드>/<날짜>   # 배치_YYYYMMDD_블로그명.zip
```
- 배치 폴더: `blog/posts/<키>/<날짜>/배치_YYYYMMDD_<블로그명>/`
- build-batch 가 "검수 N건"을 내면 **source.md·meta.json 을 고쳐 0건이 될 때까지 다시 빌드**한다
  (분량, 금지 표현, 접속어 반복, 링크 1~3개, 표 유무, 도입·마무리 연속/횟수, 제목 어미, 3개 글 이상 같은 문장, 해시태그 30개).
  검수 결과는 배치정보.md 맨 아래에 자동으로 들어간다.
- 썸네일은 contact sheet(스크래치패드 `sheet.mjs`)로 모아 Read 로 확인: 제목이 넘치거나 줄이 4줄 이상이면 cover.title 을 줄인다.

## 4단계 — 전달

1. 커밋 후 `git push -u origin <브랜치>` (브랜치는 전날 브랜치에서 `blog-<날짜>` 로).
2. `SendUserFile`: 블로그별 압축파일(attach: 겜테크 → 대학생 → 본진)과 썸네일 모음 이미지 1장(render).
3. 채팅 보고는 짧게: 블로그별 키워드 목록(시리즈면 원글), 예약 시각표 요약, 쇼핑커넥트 넣을 글, 사용자가 발행 전에 직접 확인할 것, 검수 결과 한 줄.
