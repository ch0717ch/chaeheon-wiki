블로그나 웹사이트를 운영한다면 알아둘 소식이 있어요. **OpenAI, 구글, 마이크로소프트, 앤트로픽**이 웹사이트가 **AI 학습용 데이터 수집을 한 번에 거부**할 수 있는 공통 표준을 지원하기로 했다는 보도가 나왔습니다.

지금까지는 회사마다 다른 크롤러 이름을 하나하나 막아야 했는데, 앞으로는 **robots.txt에 항목 하나**로 생성형 AI 학습 수집을 거부할 수 있게 된다는 내용이에요. 다만 적용 시점은 회사마다 다릅니다.

## 무엇이 바뀌나

| 항목 | 내용 (보도 기준) |
|---|---|
| 방식 | robots.txt에 **공통 토큰** 하나 추가 |
| 효과 | 생성형 AI **학습용** 데이터를 모으는 크롤러 차단 신호 |
| 예외 | 비생성형 작업만 하는 모델에는 적용 안 됨 |
| 표준화 | IETF에 초안 제출 |
| 성격 | **자발적 준수** — 강제 수단 아님 |

## 회사별 적용 시점 (보도 기준)

| 회사 | 적용 |
|---|---|
| 앤트로픽 | **이미 적용 중** |
| OpenAI | 몇 달 안에 |
| 마이크로소프트 | 수개월 내 / 2027년 2월 1일 보도 |
| 구글 | 내년(2027년) 중 |
| 메타 | 취지 지지, 구현 약속은 안 함 |

※ 보도마다 날짜가 엇갈려요. 각 회사 공식 문서로 확인하세요.

## 마이크로소프트는 두 가지로 나눴다

마이크로소프트는 **AI 학습**과 **AI 그라운딩**(사용자 질문에 답하려고 웹페이지를 참고하는 것)을 따로 제어할 수 있게 하고, **빙 검색 순위에는 영향이 없다**고 밝혔다는 보도가 있어요.

## 블로그 운영자는 어떻게 할까

| 상황 | 선택 |
|---|---|
| 내 글이 AI 학습에 쓰이는 게 싫다 | 공통 토큰 + 기존 회사별 크롤러 차단 함께 유지 |
| AI 답변에 인용돼 유입을 원한다 | 학습만 막고 검색·그라운딩은 허용하는 방식 검토 |
| 네이버 블로그 사용자 | robots.txt를 직접 수정할 수 없어 플랫폼 정책을 따름 |

**당분간은 기존 회사별 크롤러 규칙도 유지하는 게 안전하다**는 조언이 많아요.

## 한계도 있다

- **강제력 없음**: 따르지 않는 크롤러를 막지는 못해요.
- **저작권 문제는 별개**: 이미 수집된 데이터나 보상 문제는 다루지 않아요.

## 자주 나오는 질문

**Q. 이걸 설정하면 구글 검색에서 빠지나요?**
학습 거부 신호는 검색 색인과 별개로 설계됐다는 설명이에요. 다만 회사별 문서를 확인하세요.

**Q. 티스토리·블로그스팟은요?**
플랫폼에서 robots.txt 설정을 제공하는지 확인해야 해요.
